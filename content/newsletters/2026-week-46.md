This issue is mostly about the gap between what a setting says and what it does once you measure it, from masking rules that leave the original data elsewhere on the branch to an empty resources block that changes a pod's QoS class. Our view is that reading config in review is not enough, and if you have not run it and checked the result, you are guessing. That counts most for privacy and security controls, where a rule can cover every column you listed and still miss copies of the same data sitting in other tables and payloads.
