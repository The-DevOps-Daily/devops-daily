- **Cloud & Data Infrastructure**: Provisioning reliable cloud environments and distributed data processing architectures using Terraform and AWS
- **Containerization & Orchestration**: Packaging and scaling data services and microservices with Docker and Kubernetes
- **CI/CD & Automation**: Building automated testing, deployment, and observability pipelines for data and backend engineering teams

## My Stack

### CI/CD & Version Control

- **Git & GitHub Actions** for source control, automated testing, and container image build pipelines
- **ArgoCD** for declarative GitOps deployments and continuous reconciliation on Kubernetes

### Infrastructure & Cloud

- **Terraform** for provisioning reproducible cloud and data platform infrastructure as code
- **AWS** for scalable compute, object storage, and managed data services

### Containers & Orchestration

- **Docker** for consistent local development environments and packaging data/backend services
- **Kubernetes** for orchestrating containerized microservices, batch jobs, and distributed workloads

### Monitoring & Observability

- **Prometheus + Grafana** for cluster, pipeline, and application metrics visualization
- **CloudWatch & OpenTelemetry** for centralized logging, tracing, and alerting

### Why This Stack

I chose this combination because treating both infrastructure and data pipelines as declarative code eliminates configuration drift between environments. The biggest win has been pairing GitHub Actions with ArgoCD and Terraform: every infrastructure or pipeline change goes through pull request review and rolls out predictably with a full audit trail in Git.

### One Thing I'd Change

If I were starting fresh on a new platform today, I'd standardize on `ApplicationSet` generators and strict cost-allocation tagging in Terraform from day one rather than retrofitting multi-environment GitOps templates and FinOps visibility after the cluster footprint grows.
