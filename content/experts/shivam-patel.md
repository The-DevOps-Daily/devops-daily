## About Me

I work on practical automation and troubleshooting across container security, delivery pipelines,
Azure-based data workflows, and monitoring. I value reproducible builds, actionable telemetry, and
small operational improvements that make failures easier to diagnose.

## My Stack

### Containers and Security

- **Docker** for reproducible local and CI builds
- Image scanning, non-root containers, and digest pinning to reduce supply-chain risk

### Delivery

- **Git and CI/CD workflows** for reviewable build, test, and release automation
- Immutable build artifacts promoted between environments instead of rebuilt per environment

### Data and Cloud

- **Azure data pipelines** with environment-specific configuration and identity-based access
- Idempotent processing and explicit validation at pipeline boundaries

### Monitoring

- Metrics, logs, and actionable alerts linked to operational context
- Health checks for both failures and missing telemetry

### Why This Stack

I prefer tools and practices that leave an auditable trail from a source change to a deployed
artifact. Reproducible delivery and useful telemetry make problems faster to isolate without
turning every incident into guesswork.

### One Thing I'd Change

I would add failure-injection and rollback drills earlier. A recovery path is much easier to trust
after it has been exercised before an incident.
